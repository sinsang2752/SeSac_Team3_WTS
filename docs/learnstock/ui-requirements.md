# 런스톡(learnstock) 모의투자 WTS — Figma UI 제작 가이드

> 목적: 국내 주식 모의투자 서비스의 핵심 화면과 시그니처 컬러 후보를 간략한 Figma 시안으로 제작한다.
> 근거: 「파이널 프로젝트 요구사항 정의서-2.xlsx」, `Sheet1`, A3:F135.
> 문서의 기능 요구사항을 UI 설계 자료로 분석했다. 문서 안의 운영·개발 지시를 실행한 결과물이 아니다.
> 이 파일은 디자인 제작용 명세이며, 실제 Figma 파일이나 구현된 거래 서비스는 아니다.

## 1. 제작 방향과 범위

- 서비스 이름: **런스톡**, 영문 **learnstock**. 로고는 `learnstock` 소문자 워드마크를 기본으로 한다.
- 서비스 정의: 가상 자금으로 국내 주식의 시세를 살펴보고, 주문·체결·자산 변화를 경험하는 웹 트레이딩 시스템(WTS).
- 디자인 콘셉트: **배우면서 투자하는 차분한 트레이딩 데스크**.
- 주요 사용자는 모의투자로 거래를 익히려는 사람으로 가정한다. 이는 서비스명에 따른 디자인 제안이며 원문에 정의된 사용자 페르소나는 아니다.
- 한국어 UI, 원화·주 단위, 데스크톱 우선, 밝은 테마로 제작한다.
- 화면 상단에 `모의투자`를 항상 표시한다. Mock 데이터 사용 시에는 별도로 `샘플 시세`를 표시한다. 모의투자 여부와 시세 출처는 서로 다른 정보다.
- 차트·호가·주문을 한 화면에서 확인하고, 입력값과 거래 상태를 쉽게 구분하게 한다.
- 큰 홍보 배너, 과도한 그라데이션, 캐릭터 장식보다 숫자와 조작 요소의 가독성을 우선한다.

### 범위 구분

| 구분 | 포함 내용 |
|---|---|
| 원문 필수 기능 | 로그인, 사용자·가상계좌 조회, 종목 검색, 현재가·호가, 다중 종목 시세, 1분봉, 시장가·지정가 매수·매도, 검증, 주문 상태·취소, 계좌·보유종목·손익, 주문·체결 조회 |
| 원문 중순위 중 이번 시안에 포함 | 관심종목 등록·삭제·조회. 핵심 탐색에 유용하므로 간략 구현 |
| 후속 제작 대상 | 주문 정정, 실현손익 상세, 부분체결, 실제 인증 연동에 따른 상세 가입·인증 흐름 |
| 추가 디자인 제안 | 용어 도움말, 주문 확인 모달, 시세 연결 배지, 장애 안내, 모바일 축약 화면 |
| 사용자 화면 제작 대상 아님 | Terraform, Kubernetes, Kafka, DB, 원장 내부 처리, CI/CD, Grafana, 클라우드 DR 운영 대시보드 |

사용자 화면에 Kafka·Valkey·Cognito·AWS/GCP 등의 구현 용어를 노출하지 않는다. 시스템 요구사항은 필요한 경우 `시세 연결 중`, `주문 확인 중`, `일시적으로 주문할 수 없습니다`처럼 사용자에게 필요한 상태로 표현한다. 학습 강의·퀴즈·랭킹·뉴스·AI 종목 추천은 원문에 없으므로 이번 화면에 추가하지 않는다.

### 컬러 비교 프레임 제작 지시

1. A/B/C 카드 3개를 같은 크기로 가로 배치한다. 각 카드에는 이름·한 줄 설명·HEX가 적힌 4색 스와치를 넣는다.
2. 카드 안에 동일한 워드마크, `모의투자 시작하기` 버튼, 선택된 `모의투자` 탭, 관심종목 행을 넣는다.
3. 동일한 수치 `74,500원 / ▲ +1.64%`와 빨강·파랑 미니 캔들을 배치한다.
4. A/B/C의 레이아웃·문구·수치·가격 의미색은 유지한다. 브랜드 토큰만 교체한다.
5. 비교 포인트는 “오래 봐도 편한가”, “가격 등락색과 구분되는가”, “학습 서비스와 어울리는가”로 한다.
6. 화면 전체의 대부분은 흰색·중립색으로 유지한다. 브랜드 컬러는 로고·탭·CTA·선택 상태에 집중한다.

## 4. 공통 디자인 시스템

- 글꼴: Pretendard를 우선 사용하고, 없으면 Noto Sans KR로 대체한다.
- 크기: 페이지 제목 24/32px, 현재가 28/36px, 섹션 제목 16/24px, 본문·입력 14/20px, 보조 설명 12/18px.
- 숫자는 가능하면 고정 폭 숫자(tabular figures)를 적용하고 표 안에서 오른쪽 정렬한다.
- 가격 `74,500원`, 수량 `10주`, 수익률 `+3.47%`, 시각 `10:32:15`로 표기한다. 내역에는 날짜도 함께 표시한다.
- 기본 간격 8px, 내부 패딩 16px, 큰 영역 간격 24px. 4px는 아이콘·보조 요소에 한해 사용한다.
- 패널 모서리 12px, 입력·버튼 8px, 배지 6px. 그림자는 오버레이 중심으로 제한한다.
- 기본 입력·버튼 높이 40px, 주문 CTA 44px, 표 행 높이 44px.
- 아이콘은 일관된 선형 스타일로 사용한다. 검색·별·도움말·접기·상태 표시 정도로 제한한다.
- 일반 텍스트 대비 4.5:1, 큰 글자·핵심 컨트롤 식별 대비 3:1을 디자인 검수 목표로 삼는다. 최종 색 조합은 제작 시 확인한다.
- 키보드 포커스는 브랜드 색 2px 외곽선과 2px 간격으로 표현한다. 오류는 색상뿐 아니라 원인 문구를 제공한다.

## 5. WTS 메인 화면

### 5.1 레이아웃

1440px 기준 상단 헤더 64px, 좌우 여백 24px. 본문은 `관심종목 240px + 간격 16px + 차트·호가 760px + 간격 16px + 주문 360px`로 구성한다. 세 열의 합과 여백은 정확히 1440px다.

```text
┌────────────────────────────────────────────────────────────────────┐
│ learnstock  [모의투자] [내 자산] [거래내역]   시세 상태  런스톡 사용자 │
├────────────┬───────────────────────────────────┬───────────────────┤
│ 종목 검색  │ 삼성전자 005930  ☆                 │ [매수] [매도]     │
│ 관심종목   │ 74,500원  ▲ +1,200원 (+1.64%)      │ 시장가 / 지정가   │
│            ├────────────────────┬──────────────┤ 가격              │
│ 종목명     │ 1분봉 캔들 차트    │ 매도호가     │ 수량              │
│ 현재가     │ OHLC / 시간·가격축 │ 현재가       │ 예상 주문금액     │
│ 등락률     │ 거래량             │ 매수호가     │ 주문가능금액      │
│            ├────────────────────┴──────────────┤ [모의 매수]       │
│            │ 미체결 주문 / 체결내역 / 보유종목 │ 상태·도움말       │
└────────────┴───────────────────────────────────┴───────────────────┘
```

- 중앙 종목 헤더 아래에 차트 480px, 간격 16px, 호가 264px를 배치한다.
- 차트·호가 패널 높이는 약 460px, 하단 내역은 약 280px로 한다.
- 검색·목록·내역은 필요한 패널 내부에서 스크롤한다. 주문 버튼은 기본 화면 안에 보이게 한다.
- 주 내비게이션은 `모의투자 / 내 자산 / 거래내역` 세 가지로 단순화한다.

### 5.2 검색·관심종목

- 검색 Placeholder: `종목명 또는 종목코드 검색`.
- 검색 결과: 종목명, 6자리 종목코드, 현재가, 등락률, 관심 별 버튼.
- 종목 선택 시 중앙 헤더·차트·호가·주문 대상 종목이 함께 변경된다.
- 별 선택은 관심종목만 추가·삭제하고 행 선택과 분리한다.
- 관심종목이 없을 때: `관심종목을 추가해 보세요` / `종목을 검색하고 별을 눌러 등록할 수 있어요.`
- 검색 결과 없음: `검색 결과가 없습니다. 종목명이나 코드를 확인해 주세요.`
- 여러 관심종목의 가격이 갱신되는 모습을 보여주되, 동시 시세 구독 한도는 설정값으로 취급한다. 원문 비고의 40개를 UI의 확정 정책으로 사용하지 않는다.

### 5.3 현재가·차트·호가

- 종목 헤더: 이름·코드·관심 별, 현재가, 전일 대비 금액·등락률, 시세 기준 시각.
- 차트는 **1분봉**만 필수로 만든다. 일봉·주봉·월봉 전환을 동작하는 기능처럼 추가하지 않는다.
- 캔들, 거래량, 시간축, 가격축, 현재가 선, 선택 캔들의 OHLCV 툴팁을 표현한다.
- 차트 데이터 없음: `아직 표시할 차트가 없습니다.` 시세 로딩과 오류를 별도 상태로 둔다.
- 호가창은 시안에서 매도 5단계·매수 5단계로 간략화한다. 이는 시각화 예시이며 원문에 호가 단계 수는 지정되어 있지 않다.
- 높은 가격을 위에, 낮은 가격을 아래에 두고, 최우선 매도·매수호가가 가운데에서 맞닿도록 한다.
- 매도호가 영역은 옅은 파랑, 매수호가 영역은 옅은 빨강 배경을 쓴다. 각 영역을 글자로 명시한다.
- 호가의 매수·매도 구분과 전일 대비 상승·하락은 별개다. 가격 등락은 부호와 지정 의미색으로 표현한다.
- 호가 클릭은 지정가 입력을 돕는 제안 기능이다. 클릭만으로 주문을 제출하지 않는다.

### 5.4 주문 패널

입력 순서: **매수·매도 → 시장가·지정가 → 가격 → 수량 → 금액 확인 → 모의 주문**.

| 요소 | UI 동작 |
|---|---|
| 주문 방향 | `매수` / `매도` 탭. CTA도 `모의 매수` / `모의 매도`로 변경 |
| 시장가 | 가격 입력 비활성화, `현재 시장가격으로 체결` 표시. 금액은 예상값으로 표시 |
| 지정가 | `주문가격` 입력 활성화. 가격 조건 충족 시 모의 체결한다는 도움말 |
| 수량 | 양의 정수 입력, 단위 `주`, 간략 시안에서는 직접 입력·증감 버튼만 제공 |
| 매수 가능 정보 | 예수금, 주문 예약금, 주문가능금액을 구분 |
| 매도 가능 정보 | 보유수량, 매도 예약수량, 매도가능수량을 구분 |
| 금액 요약 | 주문가격 × 수량. 시장가는 예상 주문금액으로 표시 |
| 최종 버튼 | 입력 오류·제출 처리 중에는 비활성화, 로딩 문구 `주문 요청 중…` |

신규 사용자에게 지급되는 초기 자금은 설정값이다. 시안은 원문의 예시인 `100,000,000원`을 사용하되 `시안 예시`라는 제작 주석을 둔다. 사용자에게 확정 금액을 보장하는 홍보 문구는 작성하지 않는다.

수수료·세금·호가단위·시장 운영시간·주문 만료는 원문에서 확정되지 않았다. 별도 정책을 임의로 확정하지 말고, 이번 샘플 계산은 수수료·세금 제외라고 제작 주석에 적는다.

### 5.5 주문 확인·피드백

확인 모달 제목: `모의 매수 주문을 확인해 주세요`.

- 종목, 방향, 주문유형, 가격 또는 시장가, 수량, 주문금액을 표시한다.
- 하단 설명: `가상 자금으로 진행되는 모의투자입니다.`
- 버튼: `돌아가기` / `모의 매수 주문하기`.
- 시장가는 `체결 시점에 따라 예상금액과 달라질 수 있어요.`를 표시한다.
- 서버의 접수 응답을 받기 전에는 `주문 완료`나 `체결 완료`를 표시하지 않는다.
- 지정가는 접수 후 `주문이 접수되었습니다. 지정한 가격 조건을 기다리고 있어요.`로 안내한다.
- 체결 이벤트를 받으면 별도로 `삼성전자 10주가 모의 체결되었습니다.`를 표시한다.
- 모달·CTA의 중복 클릭을 막는다. 중복 주문 방지는 서버 기능이지만 UI에도 제출 중 상태를 제공한다.
- 통신 시간초과 시 `주문 결과를 확인하고 있어요. 거래내역에서 상태를 확인해 주세요.`를 표시한다. 결과가 불명확한 주문을 단순 실패로 처리하고 재주문을 유도하지 않는다.

## 6. 주문 상태와 예외 시안

| 원문 상태 | 사용자 표기 | 시안 표현 |
|---|---|---|
| `RECEIVED` | 접수됨 | 중립 배지, 접수 시각 |
| `ACCEPTED` | 체결 대기 | 강조 배지, 미체결 수량, 취소 버튼 |
| `FILLED` | 체결 완료 | 완료 배지, 체결가격·수량·시각, 취소 불가 |
| `CANCELLED` | 취소됨 | 중립 배지, 취소된 수량 |
| `REJECTED` | 거절됨 | 오류 배지와 구체적인 거절 사유 |

예시 흐름은 `접수됨 → 체결 대기 → 체결 완료`다. 실제 가능한 상태 전이와 취소 가능 여부는 서버 응답을 따른다. UI의 `취소 요청 중`은 임시 표시 상태이며 원문의 주문 상태 코드에 새 상태를 추가하라는 의미가 아니다.

| 상황 | 문구·동작 |
|---|---|
| 수량 미입력·0·음수·소수 | `수량은 1주 이상의 정수로 입력해 주세요.` |
| 지정가 미입력·0 이하 | `주문가격을 올바르게 입력해 주세요.` |
| 매수 가능 금액 초과 | `주문가능금액이 부족합니다.` 가능 금액을 바로 아래 표시 |
| 매도 가능 수량 초과 | `매도가능수량을 초과했습니다.` 예약수량을 포함해 설명 |
| 취소 확인 | `미체결 주문을 취소할까요?` / 종목·가격·미체결 수량 / `유지하기`, `취소 요청` |
| 취소와 체결이 동시에 발생 | `이미 체결되어 취소할 수 없습니다.` 최신 주문·계좌 상태 갱신 |
| 취소 처리 중 | `취소 요청 중…` 중복 클릭 차단. 응답 전 예약금·수량 해제 표시 금지 |
| 시세 재연결·지연 | 마지막 갱신 시각과 상태 배너. 실시간인 것처럼 표시하지 않음 |
| 시세 신뢰 불가 | 주문 잠금과 `최신 시세를 확인한 뒤 주문할 수 있어요.`를 제안 상태로 제작 |
| 서비스 장애 | `일시적으로 주문할 수 없습니다. 잠시 후 다시 확인해 주세요.` 조회 데이터는 기준 시각 표시 |
| 세션 만료 | `로그인이 만료되었습니다. 다시 로그인해 주세요.` 로그인 화면으로 연결 |

시세 지연의 판정 시간·주문 잠금 조건·복구 시점은 제품 정책 확인이 필요하다. 원문에 없는 자동 임계값을 확정하지 않는다. 장애 관련 UI는 원문의 운영 요구사항을 사용자 경험으로 보완한 제안이다.

## 7. 내 자산 화면

상단 카드: **총 자산 / 예수금 / 보유종목 평가금액 / 평가손익·수익률**.

예수금 상세에는 `전체 예수금`, `주문 예약금`, `주문가능금액`을 표시한다. 예약금은 예수금에 포함된 금액이므로 총 자산에서 한 번 더 빼지 않는다.

보유종목 표는 `종목명 / 보유수량 / 매도 예약수량 / 매도가능수량 / 평균매입단가 / 현재가 / 평가금액 / 평가손익 / 수익률`로 구성한다. 종목 클릭 시 해당 종목 WTS로 이동한다.

- 보유종목이 없을 때: `아직 보유한 종목이 없어요.` / `첫 모의투자 시작하기`.
- 평균매입단가, 평가손익, 주문가능금액 옆에는 짧은 용어 도움말을 제공한다.
- 실현손익 상세는 원문 우선순위 ‘중’에 맞춰 후속 시안으로 분리한다. 평가손익과 합쳐 단일 수익처럼 표시하지 않는다.
- 근거 데이터가 없는 자산 추이 그래프는 추가하지 않는다.

### 계산이 맞는 공통 샘플 데이터

아래 값은 UI 시안용 가상 데이터이며 현재 시장가격이 아니다. 모든 화면에서 동일하게 사용한다.

| 항목 | 시안 값 |
|---|---:|
| 초기 자금 예시 | 100,000,000원 |
| 삼성전자 보유수량 | 100주 |
| 평균매입단가 | 72,000원 |
| 매입금액 | 7,200,000원 |
| 현재가 | 74,500원 |
| 전일 종가 | 73,300원 |
| 전일 대비 | +1,200원 / +1.64% |
| 평가금액 | 7,450,000원 |
| 평가손익 / 수익률 | +250,000원 / +3.47% |
| 예수금 | 92,800,000원 |
| 미체결 지정가 매수 | 74,000원 × 10주 |
| 주문 예약금 | 740,000원 |
| 주문가능금액 | 92,060,000원 |
| 미체결 지정가 매도 | 75,000원 × 20주 |
| 매도 예약수량 / 가능수량 | 20주 / 80주 |
| 총 자산 | 100,250,000원 |

검산 기준: 총 자산 = 예수금 + 평가금액. 주문가능금액 = 예수금 − 주문 예약금. 매도가능수량 = 보유수량 − 매도 예약수량. 평가손익률 = 평가손익 ÷ 매입금액. 매도 예약수량도 체결 전에는 보유수량과 평가금액에 포함된다.

이 샘플은 최초 매수 이후 실현손익·수수료·세금·추가 입출금이 없다는 가정이다. 확인 모달의 신규 주문 샘플과 기존 예약 주문을 서로 다른 주문으로 표시한다.

프로토타입 검증 예: 현재가 74,500원에 신규 시장가 매수 10주가 전량 체결되고 가격이 그대로인 분기에서는 예수금 92,055,000원, 보유수량 110주, 평가금액 8,195,000원, 총 자산 100,250,000원, 주문가능금액 91,315,000원이다. 기존 예약 주문 두 건은 유지된다고 가정한다. 평균매입단가는 약 72,227.27원이며 화면 표시 반올림과 내부 계산 정밀도를 구분한다.

## 8. 로그인과 거래내역

### 로그인

- 프레임 `06_Login`, 1440 × 1024. 중앙 420px 카드와 간단한 브랜드 소개로 구성한다.
- 제목: `투자를 배우는 첫걸음, 런스톡`.
- 설명: `가상 자금으로 국내 주식 거래를 경험해 보세요.`
- MVP 기본 버튼: `데모 계정으로 시작하기`. Mock Login 가능이라는 원문을 반영한다.
- 로그인 직후 사용자 정보·가상계좌가 준비된 WTS로 이동한다. 계좌 준비 중 상태도 제공한다.
- 이메일 가입·비밀번호 찾기·소셜 로그인 등 원문에 정의되지 않은 상세 인증 UI는 별도 확장으로 둔다.

### 거래내역

- 프레임 `07_Trade-History`, 1440 × 1024.
- 탭: `주문내역` / `체결내역`.
- 조회 보조 UI 제안: 기간·종목·매수/매도·상태 필터. 날짜 조건은 시작일과 종료일로 표현한다.
- 주문내역 열: 주문시각, 종목, 매수/매도, 시장가/지정가, 주문가격, 주문수량, 체결수량, 미체결수량, 상태, 취소.
- 체결내역 열: 체결시각, 종목, 매수/매도, 체결가격, 체결수량, 체결금액.
- 행 선택 시 주문번호와 상태 변경 시각을 보여주는 상세 패널을 제안한다.
- 빈 상태: `조회한 기간에 내역이 없습니다.` 필터 초기화 버튼 제공.
- 주문 정정은 후속 기능으로 남기며 기본 시안에 활성 버튼을 노출하지 않는다.
- MVP는 전량체결 기준으로 제작한다. 부분체결 변형은 확장 페이지에만 두고 확정된 서버 상태 코드처럼 이름을 만들지 않는다.

## 9. Figma 파일 구조·프로토타입

### 권장 페이지

```text
00_Brief          범위·정책 확인사항
01_Foundations    컬러 3안·타이포·간격
02_Components     버튼·입력·행·상태·모달
03_Screens        WTS 3안·자산·로그인·거래내역
04_States         오류·로딩·빈 상태·시세 재연결
05_Prototype      핵심 연결 흐름
```

컬러 비교는 로컬 변수 또는 컬러 스타일로 A/B/C를 교체할 수 있게 구성한다. 편집 가능한 텍스트·도형·컴포넌트를 사용하고 전체 화면을 단일 이미지로 만들지 않는다. 반복 요소에는 Auto Layout과 컴포넌트 인스턴스를 적용한다.

### 연결할 핵심 흐름

1. 데모 로그인 → WTS → 종목 검색 → 종목 선택 → 관심종목 등록.
2. 시장가 매수 → 수량 입력 → 확인 모달 → 요청 중 → 체결 결과 → 자산 갱신.
3. 지정가 매수 → 확인 모달 → 체결 대기 → 주문 예약금 확인 → 취소 요청 → 취소됨·예약금 해제.
4. 매도 탭 → 보유·예약·가능수량 확인 → 지정가 매도 → 체결 대기.
5. 가능 금액·수량을 넘긴 입력 → 필드 오류 → 수정 후 CTA 활성화.
6. 내 자산의 보유종목 클릭 → 같은 종목의 WTS.
7. 시세 연결 종료 → 마지막 시각·재연결 안내 → 연결 복구.

프로토타입 시세와 체결은 정해진 가상 시나리오로 표현한다. 실제 API 연동이나 실제 거래 기능이 완성된 것으로 설명하지 않는다.

### 선택 확장: 좁은 화면

- 1280px에서는 관심종목 영역을 접는 안을 제안한다. 3열을 무리하게 줄여 숫자가 잘리게 하지 않는다.
- 모바일 390 × 844 시안이 필요하면 `차트 / 호가 / 주문 / 내역`을 탭으로 나눈다.
- 모바일 주문 화면에서도 종목·가격·수량·가능 금액과 CTA를 함께 확인할 수 있게 한다.
- 이번 최초 시안의 우선순위는 데스크톱이다.

## 12. 제작 완료 체크리스트

- [ ] learnstock·런스톡 표기가 일관되고 모의투자 표시가 보인다.
- [ ] A/B/C 색상 시안은 동일한 구성·문구·데이터로 비교할 수 있다.
- [ ] 1440px에서 현재가·1분봉·호가·주문 버튼을 함께 볼 수 있다.
- [ ] 종목 선택 시 차트·호가·주문 대상이 일치한다.
- [ ] 시장가·지정가와 매수·매도 입력 차이가 표현되어 있다.
- [ ] 예수금·예약금·주문가능금액, 보유·예약·매도가능수량이 구분된다.
- [ ] 주문 접수·체결·취소·거절·결과 확인 중 상태를 구분한다.
- [ ] 금액 부족·수량 초과·중복 클릭·시세 재연결 상태가 있다.
- [ ] 예약 주문·신규 주문·체결 후 자산의 샘플 수치가 서로 맞는다.
- [ ] 빈 상태·로딩·오류와 마지막 시세 갱신 시각을 표현한다.
- [ ] 주요 글자·컨트롤 대비와 키보드 포커스를 확인한다.
- [ ] 원문 기능, 디자인 제안, 후속 기능, 미확정 정책이 구분되어 있다.
